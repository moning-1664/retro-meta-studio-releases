작업 이력과 복구

앱이 실행한 파일 작업의 상태를 확인하고, 지원되는 작업은 실행 취소하며, 도중에 끊긴 작업은 복구합니다. 복사·이동·삭제처럼 파일을 실제로 바꾸는 작업은 정전, 드라이브 분리, 앱 종료 같은 사고로 중간에 멈출 수 있습니다. 이 페이지는 그런 경우 어떤 상태가 표시되고 무엇을 선택해야 하는지 설명합니다.

어떤 때 쓰나

  • 전송·이동·삭제가 도중에 멈췄거나 앱이 갑자기 종료되었을 때
  • 끝난 작업의 범위와 오류를 나중에 확인하고 싶을 때
  • 방금 한 작업을 되돌리고 싶을 때

여는 곳

작업 이력 창에서 작업 종류·대상·상태를 확인하고 항목을 고릅니다. 복구 안내가 나타났다면 원본·대상·백업을 그대로 둔 채 해당 항목을 엽니다. 앱은 이 세 가지를 기준으로 상태를 검사하기 때문입니다. 복구가 필요한 작업이 발견되면 복구 안내에서 작업 이력을 엽니다. 하단 알림 이력은 메시지를 다시 읽는 창으로, 파일 복구 작업 이력과 구분합니다.

위 그림은 하단의 알림 이력입니다. 오류 메시지를 다시 읽는 용도이며, 파일 복구의 작업 이력과 구분합니다. 복구 필요 안내가 뜨면 안내에서 작업 이력을 열어 해당 파일 작업을 처리합니다.

상태와 해야 할 일

상태뜻할 일
완료작업이 끝났습니다.실행 취소가 가능한 작업이면 항목에 버튼이 나옵니다. 버튼이 없으면 취소를 지원하지 않는 작업입니다.
복구 필요작업이 중간에 끊겨 파일과 기록의 상태를 검사하고 복구해야 합니다.복구 를 실행합니다. 끝날 때까지 원본과 백업을 지우지 않아야 합니다.
복구 실패복구가 끝나지 않았습니다.오류와 남은 백업을 보관하고 아래 선택지에서 정합니다.
기록 닫기(백업 유지)현재 파일을 그대로 두고 자동 복구를 끝냅니다. 백업은 남깁니다.현재 파일이 맞다고 판단될 때 고릅니다. 이후 되돌릴 방법은 남겨 둔 백업을 직접 확인하는 것뿐입니다.
수동 복구작업의 소유자(작업을 실행한 앱)를 확인할 수 없는 상황입니다.같은 파일을 쓰는 다른 앱이 꺼져 있는지 확인한 뒤, 검사를 거쳐 처리합니다.

복구가 되는 범위

  • 복구는 앱이 실행한 파일 작업과 그 백업을 기준으로 이루어집니다.
  • 외부 프로그램이 임의로 바꾼 파일, 탐색기에서 직접 옮기거나 지운 파일은 되돌리지 않습니다.
  • 작업마다 실행 취소와 복구 조건이 다릅니다. 영구 삭제처럼 제한이 있는 작업은 실행하기 전에 안내가 나옵니다.

복구하기 전에

  • 같은 보관소나 파일을 쓰는 다른 앱이 있다면 그 앱의 작업을 먼저 끝냅니다. 두 곳에서 동시에 같은 파일을 만지면 검사가 어긋날 수 있습니다.
  • 복구 전후의 파일과 기록이 예상과 다르면 검사가 실패할 수 있습니다. 남은 파일과 오류 메시지는 지우지 않아야 합니다.
  • 이동 중이던 작업이라면 원본 드라이브와 대상 드라이브가 모두 연결되어 있는지 확인합니다.
주의

복구에 실패한 뒤 원본을 다시 덮어쓰거나 백업부터 지우면 원인을 알 수 없게 되고 되돌릴 방법도 사라집니다.

문제 해결

실행 취소 버튼이 없습니다.

모든 작업이 취소를 지원하지는 않습니다. 영구 삭제 등은 실행 전 안내를 기준으로 처리합니다.

복구가 반복해서 실패합니다.

다른 앱의 사용 여부와 기기 및 드라이브 연결을 확인하고 백업을 유지합니다. 앱 버전·작업 종류·오류 내용을 적어 Q&A에 알려 주시기 바랍니다. 이때 로그에 포함된 계정명과 개인 경로는 지우고 올립니다.

작업 이력에 오래된 항목이 계속 남아 있습니다.

완료된 항목은 기록일 뿐 파일에 영향을 주지 않습니다. 설정의 고급에서 종료 시 백업 정리·백업 개수·백업 최대 용량을 지정합니다. 복구가 필요한 작업의 백업은 일반 완료 기록 정리와 구분해 유지합니다.

원본 백업과 앱 작업 백업

처음 편집하기 전에는 앱과 프론트엔드의 쓰기 작업을 끝낸 뒤, 탐색기에서 게임목록 폴더를 다른 위치에 복사합니다. 따로 연결한 ROM·미디어 폴더도 원본 보관이 필요하면 함께 복사합니다. 보관소(Archive) 백업에는 앱을 종료한 상태의 보관소 DB·설정과 보관 미디어·ROM이 필요합니다. db/cache는 다시 읽어 만들 수 있는 목록 캐시이며 보관소 원본을 대신하지 않습니다.

앱의 로컬 작업 기록은 실행 파일 옆 db/paste_undo, 보관소 작업 기록은 db/archive_undo에 있습니다. 일부 교체 원본은 대상 파일 옆의 .rms-backup 파일로 보관합니다. 이 파일들은 작업 기록과 함께 사용하므로 임의로 이름을 바꾸거나 옮기지 않습니다.

설정의 고급에서 종료 시 백업 정리·보관 개수·최대 용량을 정합니다. 백업이 정리되면 해당 작업을 되돌릴 수 없을 수 있습니다. 복구 중인 자료와 원본 복사본은 별도로 보관합니다.

실행 취소 지원 범위

작업범위와 제한
로컬 메타데이터 저장지원되는 로컬 저장은 작업 기록과 원본 사본으로 되돌립니다. 보관 기간과 파일 상태 검사를 통과해야 합니다.
로컬 붙여넣기·파일 작업작업 기록이 생성된 지원 작업에 실행 취소가 표시됩니다. CUE/M3U 작업은 새로 만든 구성 파일까지 기록하며, 이후 다른 게임이 참조하게 된 파일은 무조건 지우지 않습니다.
보관소(Archive) 작업보관소 전용 작업 기록으로 복구합니다. 게임별 변경 이력에서 다른 정보를 고르는 기능과 구분합니다.
UNC·매핑 네트워크 드라이브·연결 기기일반 로컬 작업의 자동 실행 취소 대상에서 제외됩니다. 실행 전 제한 안내와 결과를 읽고 원본 복사본을 유지합니다.
영구 삭제·외부 프로그램의 변경일반 실행 취소로 되돌릴 수 없습니다. 별도 백업에서 복원합니다.

실행 취소는 현재 파일 상태와 작업 소유 범위를 다시 검사합니다. 외부 변경이나 연결 불가로 거부되면 오류와 백업을 남긴 채 원인을 해결합니다. 모든 작업을 언제든 되돌리는 기능으로 사용하지 마세요.
